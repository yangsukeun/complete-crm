# 3PL 영업·월정산 저장 구현 — 운영 미적용

검증 결과: 신규 도메인/저장/API 10개 + 기존 업무영역/개인 기록 회귀 13개, 총 23개 통과. TypeScript, 변경 파일 ESLint, 전체 Next 빌드 통과. 기존 스키마와 초안을 합친 별도 임시 파일의 Prisma validate 통과(합성 localhost 연결값, 실제 DB 접속 없음). 기존 전체 저장소 린트 문제는 해결 범위 밖이다.

기준 배포 99a51fb와 개인 기록을 보존하고 feature/logistics-sales-local에서만 추가했다. 운영 push, DB 적용, 계정 변경, 실제 재무 데이터 쓰기는 하지 않았다. UI는 기존 준비 중 상태를 유지한다.

## 재사용과 분리

기존 NextAuth/getAppSession, Prisma 연결, User.id/department/accountDisabled 및 실제 부서 분류를 재사용한다. 일반 ADMIN 권한만으로는 허용하지 않는다. 대표의 정확한 ID 또는 물류/물류팀/물류창고/3pl 부서만 허용하며 매 요청 DB의 현재 값을 검사한다. 직원별 추가 권한을 만들거나 역할을 변경하지 않는다. 부서 내부 영업기록 공동 조회/작성은 이 초안의 승인 대상이며 운영 적용 전 확인이 필요하다.

기존 Quotation GET은 부서 필터가 없고 Vendor는 지급 계좌 중심이므로 새 기록을 그 모델에 넣지 않는다. 기존 견적/거래처/지급 기록은 수정하거나 복사하지 않는다. 신규 테이블 2개에 종류별 레코드를 저장한다. JSON 자료형으로 상세 필드를 보관하되 Zod strict 입력 검사, DB 종류/상태 검사, 관계 FK와 유일 인덱스를 병행한다.

## 승인할 정확한 변경

- logistics_sales_records: 문의/견적/계약/거래처/청구/수금 기록, parent FK(RESTRICT), 버전, 공급가액·VAT·귀속월·발행일·참조번호·근거. PK, parent, scope+kind, 고객 사업자번호 유일, 계약 원본 유일, 거래처별 청구참조 유일, 수금참조 유일, 청구월 인덱스.
- logistics_sales_commands: 작성자 ID, 중복키, 내용해시, 명령, 변경 전/후, DB 기록시각. actor+request_key 유일, actor+created_at 인덱스. 사용자 삭제 후에도 변경이력 보존을 위해 actor FK cascade 없음.
- 두 새 객체에만 일반 RLS, PUBLIC/anon/authenticated 직접 접근 회수. FORCE RLS·service_role 회수·기존 객체/전체 권한 변경 없음. 시퀀스 없음(UUID 서버 생성). 실제 실행 DB 역할 호환성은 적용 전 다시 확인.
- 서버 범위: GET/POST /api/logistics-sales 및 해당 도메인/Prisma 어댑터. GET은 쓰기 없음. 공개 홈페이지 접수, 파일 업로드/검색/내보내기, 직원 알림, 구매/급여/계좌는 포함하지 않음. 새 테이블은 기존 검색/내보내기 쿼리에 연결하지 않음.

## 업무 규칙과 한계

문의 원문 보존 → 견적 → 체결 근거가 있는 계약 → 거래처. 견적·청구 정정은 버전 증가 및 전후 이력, 계약된 견적 수정 차단. 계약만으로 청구/매출 생성 안 함. 거래처의 같은 월 복수 청구 허용, 발행일과 귀속월을 따로 입력한다. 공급가액/VAT/청구액과 실제 수금 기록은 별개다. 부분수금 허용, 초과수금/수금보다 작은 감액 차단. 수금 취소는 기록 정정이며 실제 환불 아님. 활성 하위 기록이 있는 부모 취소는 차단한다. 취소/정정 이유를 이력에 보존한다.

같은 actor/key의 동일 내용은 저장 결과 재사용, 다른 내용은 409. 새 키로 연타해도 버전/전환 유일 조건으로 차단한다. 실패 시 기록과 감사명령이 함께 롤백된다. 현재는 logistics scope 단일 advisory lock과 전체 조회로 정합성을 우선한 소규모 구현이다. 대량 처리 전 거래처 단위 잠금/페이지 조회 및 부하 검증이 필요하다. 같은 사업자번호의 추가 계약은 기존 거래처에 연결한다. 계약 취소는 거래처를 삭제하지 않는다. 다사업장 고객키, 입금 일괄배분/외화/세금계산서 발행은 미구현이며 추후 결정사항이다.

## 적용·복구 순서

prisma/drafts의 SQL/Prisma는 검토 초안이며 migrations 폴더에 넣지 않았다. 승인 후 분리 PostgreSQL에서 DDL/역할/동시성 검증 → 실제 DB 대상/백업 확인 → 새 객체만 마이그레이션 → 서버 배포 → 지원된 로그인으로 권한·저장·재시도 확인 → UI 입력 연결 순서. 운영 검증용 실제 재무 데이터는 만들지 않는다.

실패 시 신규 API/UI 코드만 비활성화하거나 이전 99a51fb로 복귀한다. 새 테이블은 기록 보존하며 자동 DROP하지 않는다. 기존 데이터/로그인/개인메뉴에는 DB 변경이 없다. 보유기간·보관/삭제·정정 권한은 재무기록에 별도 확정해야 하며 홈페이지 문의의 5년 결정을 모든 회계기록에 자동 적용하지 않는다.

로컬 검증은 합성 입력과 트랜잭션 모의 DB다. postgres/psql/docker 실행 명령을 찾지 못했다. 실제 PostgreSQL DDL/잠금/격리 E2E 및 운영 로그인 E2E는 미검증이다. 새 설치·DB·키는 만들지 않았다.
