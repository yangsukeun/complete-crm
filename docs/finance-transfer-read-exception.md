# 지정 이체 담당자 전체 조회 예외 (2026-10-27)

사용자 정정: “이체담당자는 다 보이게 해줘”, “CRM에서”. 이전 대표 전용 전체 조회 정책에 아래 읽기 예외를 추가한다.

- 기존 `CompanyInfo.transferExecutorIds`만 사용한다. ADMIN/EXECUTIVE 직급으로 이체 담당자를 추정하지 않는다.
- 운영 읽기 집계: 지정 ID 3개 중 활성 사용자와 일치 1개, 사용자 레코드와 불일치 2개. 계정·부서·지정값을 변경하지 않았다. 존재하지 않거나 비활성인 계정은 허용하지 않는다.
- 지정된 활성 이체 담당자는 전체 지출 목록·상세·프로젝트 지출 집계·관련 은행정보·첨부 다운로드를 읽을 수 있다. 기존 알림도 같은 읽기 범위 검사를 사용한다.
- `resolveFinanceAccess`의 read/write 모드를 분리했다. 읽기 예외는 상태변경·삭제·일괄 완료·거래처 변경/삭제 범위를 넓히지 않는다. 기존 승인 조건도 유지한다. 실제 송금 기능을 추가하지 않았다.
- 목록의 `canActWithinScope`는 서버가 계산한다. 화면은 읽기만 가능한 행의 변경/승인/완료/삭제/일괄 선택을 숨긴다. 직접 API 요청은 별도로 write 범위를 검사한다.
- 지정 해제 시 다음 조회부터 본인 또는 기존 팀 범위로 복귀한다.
- DB 직접 접근 차단 3테이블 및 Drive 공유 설정 변경은 별도 승인 대기이며 이번 배포에 포함되지 않는다.

검증: 합성 사용자 테스트에서 지정 이체 담당자의 타팀 상세/은행/첨부 읽기 성공과 같은 타팀 변경·삭제 거부, 미지정 ADMIN의 본인 범위 및 지정 해제 복귀를 확인한다. 실제 직원 메시지·지급·재무 쓰기 시험은 하지 않는다.
