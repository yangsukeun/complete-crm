# PDF 업로드 복구 보완

기준 운영 2a9e72a. 실제 업무 PDF는 읽거나 복제하지 않았다.

확인된 코드 결함: Drive의 영구 오류도 모두 502로 변환하고, 청크 실패 후 상태 조회가 성공하면 클라이언트 재시도가 무제한 이어질 수 있다. 308에 Range가 없어도 전송한 크기만큼 성공으로 가정했다. 사용자 화면의 재시도 17회와 부합하지만 최초 실패의 실제 HTTP 응답은 미확보이므로 원인을 확정하지 않는다.

변경: 404/410 만료 및 기타 영구 오류를 재시도 가능한 오류와 구분, 전송 오류 원문/세션 URL 로그 배제, 8회 상한, 명시적 상태/Range 검사, 불확실한 pause 복구에서 로컬 offset 추정 금지, Google 308 자동 리디렉션 방지, 서버 전송 60초 제한. 기존 2MiB 청크와 사용자별 서명 세션을 유지하며 파일당 2GiB 상한을 추가했다. 새 서비스/키/공개 공유/Drive 권한 변경 없음.

합성 테스트: 309200바이트와 12MiB PDF 형식 표식이 있는 합성 바이트를 모의 전송하고 바이트 일치 확인, 응답 유실 재개, 만료 즉시 중단, 상태 조회 성공 중 반복 실패 8회 중단, 로그인/소유자/범위 검사. 이는 실제 Drive 업로드/다운로드나 PDF 렌더링 검수가 아니다. 22개 테스트 통과. 타입·변경 파일 lint 통과.

남은 검수: 정상 CRM 로그인 세션으로 승인된 비공개 시험 폴더에 작은/큰 유효 PDF 업로드, pause/resume, 목록 재조회, 다운로드 바이트 대조 및 삭제 없이 시험 파일 식별. 현재 지원 검수 브라우저는 로그아웃 상태이며 거절된 Chrome/로컬 UI 접근은 우회하지 않는다. 실패한 요청의 HTTP/Google 상태 코드만 있으면 최초 실패 분류가 가능하며 업무 파일 내용은 필요 없다.

참고: https://developers.google.com/workspace/drive/api/guides/manage-uploads (308 Range, 404 만료, 256KiB 청크 배수), https://vercel.com/docs/functions/limitations (요청/응답 4.5MB 제한). 2GiB 상한은 제품의 안전한 제한이며 2GiB 실제 업로드 성공을 검증했다는 뜻이 아니다.
