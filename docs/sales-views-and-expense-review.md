# 3PL 업무 진입 및 지출 접근 검토 (2026-10-27)

## 이번 화면 변경
- `/logistics/sales?view=inquiry|quote|contract|client|invoice`: 단계별 목록/입력, 선행 기록 선택, 기존 상세·정정·취소·다음 단계 처리. 기존 두 테이블/API만 사용.
- `/logistics/purchases`: 현재 사용자와 실제 부서를 다시 확인한 후 기존 결제 요청 화면 사용. 기존 지출 권한 정책을 변경한 것으로 주장하지 않음.
- 합성 HTTP 저장/재조회 UI 검증: 문의 실패·같은 키 재시도, 견적→계약→거래처→청구, 새로고침, 모바일 폭. 실제 운영 재무 데이터를 생성하지 않음.
- 실제 로그인 브라우저 E2E 및 실제 재무 저장 검수는 이번 UI 시험과 별개. 기존 API 권한/멱등성/정정/부분수금 회귀 테스트 사용.

## 지출 제한: 별도 미완료
현재 `finance-scope.ts`는 ADMIN/EXECUTIVE 및 이체 담당자에게 전체 조회를 허용한다. 사용자가 요청한 대표 전체/일반 본인/기존 팀 담당자 소속 팀 원칙과 차이가 있다.
변경 점검 대상: finance 요청 목록·상세·PATCH·DELETE·batch-complete, 프로젝트 상세의 paymentRequests/paymentSummary, 알림 집계, vendor 은행정보, file-download 및 업로드 연결.
`app/api/upload/route.ts`는 Drive 업로드 후 anyone-with-link 권한 부여 경로가 있으며 file-download는 공개 Blob URL도 허용한다. 이는 코드상 공개 링크 지원 증거이며 특정 운영 파일 유출을 확인한 것은 아니다. 실제 파일/개인정보를 조회하지 않았다.
서버 목록/상세 제한만으로 기존 외부 공개 파일 URL을 차단할 수 없다. 기존 지출 첨부의 저장 공급자·파일 연결을 확인하고, **지출 첨부에 한정한 기존 공개 공유 회수 및 인증 다운로드로 전환**하는 별도 구체 범위를 검토해야 한다. 무관한 공통 자료의 공유 권한은 변경하지 않는다. 현재 외부 파일 권한 변경/삭제는 미실행.

## OCR 연결 준비 범위
현 CRM에는 실제 입고·로트 저장 모듈이 확인되지 않았다. OCR 작업의 resume 링크/로컬 worker 시험은 실제 입고 연동 완료가 아니다.
제안 객체: 장치 등록(사용자·허용 고객사·만료·회수), OCR 작업(고객사·비공개 원본 참조·revision·상태·lease), 감사 이벤트(배정/결과 수락/회수). 기존 실제 ERP 객체와 대조 후 확정하며 이번 변경에는 생성하지 않는다.
필요 API: 원자적 작업 배정, 배정 장치의 원본 읽기, 최신 revision에 대한 결과 제출·수락. 결과는 needs_review까지만; 입고 확정은 기존 담당자 인증과 별도 검수/저장 경로가 필요하다.
15분 토큰/7일 파일럿/DPAPI 저장은 OCR 측 제안이며 사용자 장치 인증 승인이 아직 없다. 새 키·장치 지속권한·사진 저장 권한·운영 테이블을 만들지 않았다.
