# CS TEST 초기 진입 개선

- 기존 저장 사본은 수동 목록 조회 뒤 직접 열어야 했다. 이제 진입 시 격리 TEST API를 조회한다.
- 사본이 하나면 저장된 TEST 상태·버전·이력을 자동으로 복원한다. 여러 사본이면 임의 선택하지 않고 목록에서 선택한다.
- 조회 중 입력을 잠그며 언마운트된 요청은 취소한다. 실패 시 다시 불러오기를 제공한다. 기존 저장/재열기 및 버전 충돌 처리 경로는 유지한다.
- 알려진 synthetic- 사본은 가상 자료로 표시한다. 다른 사본도 실제 자료로 인증하지 않고 원장 대조 필요로 표시한다.
- 원본 407/337 차이, 직원 연결, 실제 이전 미완료를 첫 화면에 명시한다. 합성 예제를 자동 생성하거나 저장하지 않는다.
- DB/운영 연차 API/권한/메일/새 외부 송신 변경 없음.

## 검증과 자료 확인

자동 불러오기, 빈/여러 사본, 권한·저장소 오류, 응답 형식 및 ID 불일치, 알려진 합성 자료 구분을 독립 테스트했다. 기존 신청·승인·집계·원장 검수와 함께 23개 테스트 통과. TypeScript와 변경 파일 ESLint 통과.

작업 폴더의 CS 조사 자료에는 새 원장 사본이 없었다. 연결 Drive에서 2026-11-04 10:00 UTC 이후 수정되고 이름에 휴가/연차/CS컴플리트를 포함하는 자료의 메타데이터를 검색했으나 결과가 없었다. 이는 다른 이름/위치에 원장이 없다는 증거가 아니다. 기존 70건 차이 및 안정적 직원 ID 연결은 미확인이고 실제 이전은 0건이다.

전체 Next 빌드는 제한 환경의 .next 디렉터리 생성 EPERM 후 승인된 호스트 실행에서 통과했다. 로컬 더미 DB 주소를 사용했으며 운영 DB에는 연결하지 않았다.

브라우저 안전 중단 및 다른 담당자의 PC 화면 사용을 존중해 화면 조작하지 않았다. 실제 로그인 UI 검수는 미실시다. 합성 초기 조회 검증은 실데이터 검증이나 실제 직원 세션 검수를 뜻하지 않는다. 기존 저장 PUT/버전 충돌 로직은 변경하지 않았고 이번에는 실서버 저장을 재시험하지 않았다.
