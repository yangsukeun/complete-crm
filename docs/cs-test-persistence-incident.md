# CS 휴가 지속성 신고 조사

## 대상과 확인 범위

김소윤 매니저의 신고에는 정확한 주소가 없으므로 Gemini 원본 / CRM TEST / 운영 연차 중 어느 화면인지는 미확정이다. 실사용 계정 조회·신청·승인·삭제를 하지 않았다. 브라우저 안전 중단을 유지했다.

- `/cs-tools/test`: 배포 커밋 8243a85의 신청 `request`와 승인 `change`는 React state와 dirty만 변경한다. 별도 `serverSave` 호출 전에는 DB에 저장하지 않는다. 저장하지 않은 신청은 재접속 후 없고, 저장하지 않은 승인은 기존 PENDING으로 돌아오는 실패 경로가 코드상 확정이다. 센터장이 별도 저장했는지 등 사람별 차이의 원인은 미확인이다.
- TEST에는 직원별 localStorage/sessionStorage 초안이나 저장 키 분기가 없다. 동일한 공유 TEST API와 최신 버전 확인을 쓴다. API GET은 no-store이고 현재 계정 권한을 DB에서 재확인한다. 서버는 버전 CAS로 동시 저장을 막는다. 사본 하나만 자동으로 열며 여러 개면 명시적으로 선택한다. 서로 다른 사본 선택 가능성은 신고 URL·사본 식별 전 미확인이다.
- `/cs-tools/leave`는 운영 `LeavePageClient`를 사용한다. 신청 POST `/api/leave`, 승인 PATCH `/api/leave/:id`는 서버 응답 성공 후 완료 표시한다. TEST와 같은 메모리 전용 동작이 아니다. 조회 실패 시 목록을 비우는 코드는 있으나 이번 신고의 원인인지 미확인이다. 운영 GET에는 연차 동기화가 있어 실서버 조회하지 않았다.
- Gemini 원본은 코드/원장 자료가 없어 이번 신고와 연결하지 못했다.

## 로컬 수정

신청·승인 시 변경 후보를 먼저 만들고 서버 확인 후 목록과 완료 표시를 갱신한다. 별도 저장 버튼을 누르지 않아도 해당 변경을 저장한다. 동기 ref 잠금과 입력 잠금으로 연속 클릭을 막는다. 실패 시 성공 표시를 지우고 동일 신청 ID의 초안을 메모리에 보존한다. 미저장 초안 내려받기와 같은 변경 재시도를 제공하고 추가 신청·승인은 보류한다.

PUT 응답 유실/409 시 원본 해시의 TEST 사본을 읽어 전체 payload와 버전을 대조한다. 정확히 저장된 동일 변경만 복구 성공으로 처리한다. 다른 세션의 변경은 자동 병합/덮어쓰기하지 않고 충돌을 표시한다. 자동 PUT 재시도 없음. 401/403은 저장 실패로 유지한다. 초안은 영구 저장이 아니며 실패 후 페이지를 닫기 전에 내려받아야 한다.

원본 되돌리기 동작은 미저장 변경임을 표시하도록 바로잡았다. 출퇴근 수동 입력은 기존 수동 저장 방식이며 이번 휴가 자동 저장 수정 범위와 구분한다. DB·권한·운영 연차·메일 변경 없음.

## 검증

합성 테스트 20개 통과: 직원 신청 후 새 클라이언트 조회, 승인 후 새 클라이언트 조회, 실패 후 동일 초안 재시도, 저장 응답 유실, 같은 변경 재전송, 다른 변경 동시 저장, 세션 만료/권한 거절. ESLint 및 TypeScript 통과. UI 클릭 잠금은 코드 검토했으며 실제 로그인 브라우저 검수는 수행하지 않았다.

격리 PostgreSQL 18.6 및 HTTP 시험 2개 통과: 마이그레이션 적용/트랜잭션 롤백, RLS, 비로그인/비활성 차단, 합성 직원 신청 및 센터장 승인 후 세션 재조회, 동시 저장 200/409, 재시도 중복 이력 방지, 원본/이력 불변. 첫 실행은 시험 순서 오류로 실패했고 순서 수정 후 새 클러스터에서 통과했다. 시험 서버는 종료했다. 전체 Next 빌드도 통과했다. 합성 세션은 실제 직원 로그인을 의미하지 않는다. 실제 데이터 영향·이전 0건. 원본 70건 차이와 직원 ID 매칭은 미확인이다.

이번 조치는 로컬 수정·검증까지이며 운영 배포는 별도 승인 대상이다. 신고 대상 주소를 확인해야 이 수정이 신고된 사이트를 해결하는지 판단할 수 있다.
