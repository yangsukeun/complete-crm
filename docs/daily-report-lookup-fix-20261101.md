# Daily Report 조회 오류 로컬 수정

기준: 원격 main 35c2ef710e411e83885b2e855a0940dc20cffdd9. 작업 브랜치 fix/daily-report-lookup.
홈페이지 문의 미배포 변경은 work/website-intake-storage의 명시적 stash에 보존했다:
`preserve website intake local changes before daily report fix`. 문의 코드는 이 수정에 포함하지 않는다.

## 읽기 진단
- 운영 CRM DB vgelnrycivorwczdqpsu의 DailyWorkLog 스키마는 id/userId/date/content/status이며 현재 코드 모델과 일치한다.
- 2026-10-31 조건의 DailyWorkLog 집계는 0행이었다. 본문·개인 비밀번호·토큰을 읽지 않았다. 이는 해당 테이블의 해당 날짜 저장 행이 없다는 증거이며 직원 업무 수행·다른 기록 부재나 삭제를 뜻하지 않는다.
- 배포 API는 다른 직원 일지가 없으면 404, 화면은 모든 비정상 응답을 동일한 '(불러오기 실패)'로 바꾸고 있었다. 따라서 저장 기록 없음이 장애처럼 보이는 경로를 합성 API/UI 응답 테스트로 재현했다.
- 대표 ADMIN은 기존 조회 권한을 통과한다. 실제 대표 브라우저의 해당 요청 HTTP 응답은 이번에 수집하지 않았으므로 과거 8건 각각의 응답 상태까지 직접 확인했다고 주장하지 않는다.

## 최소 수정
- 기록 없음에 WORK_LOG_NOT_FOUND, 실제 서버 오류에 WORK_LOG_READ_FAILED 코드.
- 관리자 조회는 mode=read-only로 본인 선택 시에도 초안을 만들지 않음. 기존 본인 업무일지 작성 화면의 기본 생성 경로는 유지.
- 화면은 저장된 일지 없음/저장된 빈 본문/401/403/400/서버 오류/잘못된 JSON을 구분. 오류를 일지 본문으로 넣지 않고 별도 안내와 다시 조회 버튼 제공.
- 직원/날짜 변경 시 이전 fetch 중단 및 응답 적용 전 취소 검사. 캐시 없이 조회. 실제 달력 날짜 검사와 빈 날짜 표시 보호.
- 대표/김정신/GoPro/일반 직원 권한 로직과 PATCH 작성·수정 코드는 변경하지 않음.

## 검증과 한계
- 합성 40건 통과: 저장 일지·빈 초안·없는 날짜·서버 장애, 대표 본인 read-only 무생성, 비로그인/비활성/미허용 직원 차단, 기존 김정신 5명/GoPro 일반 직원 경계, 날짜 및 JSON 처리.
- TypeScript, 변경 파일 ESLint, 전체 Next production build 통과. 기존 의존성 연결 때문에 빌드 동안만 Turbopack root를 조정했으며 next.config.ts는 원복했다.
- 실제 사용자 브라우저 클릭/전환·취소 UI와 운영 로그인 GET은 미검증. 기존 UI 접근 거절 경로 재시도 없음.
- DB 쓰기/마이그레이션/직원 역할 변경/알림/배포 없음. 기존 데이터 보존.

## 운영 반영 승인 시 다음 단계
이 브랜치의 일지 관련 파일만 배포 후보로 삼는다. 문의/비밀번호/OCR/재무 변경 제외.
배포 후 대표 기존 정상 세션에서 2026-10-31 및 저장 기록이 실제 존재하는 날짜를 조회해 네트워크 상태와 화면을 대조한다. 404 없는 기록 안내, 200 기존 본문, 세션 만료/접근 거부 안내, 빠른 직원 전환을 확인한다. 조회 전후 행 생성이 없어야 한다. 실제 직원 자료를 테스트용으로 작성하거나 제출하지 않는다.
