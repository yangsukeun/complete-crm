# 지출 범위 제한 — 2026-10-27

## 애플리케이션 변경
- 대표 ID만 전체. 일반 직원 본인. 기존 팀장/센터장과 기존 겸임 조회 대상은 기존 소속 범위만 유지. ADMIN/EXECUTIVE/이체 담당자 지정만으로 전체 조회하지 않는다.
- 매 요청마다 현재 사용자 및 비활성 상태를 확인한다. 조회·상세·변경·삭제·일괄 완료·프로젝트 지출 및 집계·알림·내보내기의 원본 목록에 같은 범위를 적용한다. GET의 과거 알림 생성 부수효과는 제거했다.
- 은행명·계좌·예금주는 대표 외 응답에서 제거. 타인 거래처 ID 직접 조회·공유 거래처 수정·비대표 거래처 삭제를 차단한다. 일반 거래처 이름/분류 목록은 기존 선택 기능을 위해 유지한다.
- 파일 다운로드 프록시는 결제 요청에 연결된 첨부의 조회 범위를 확인한다. Drive URL 변형과 쿼리 문자열 변경을 정규화한다. 이미 알려진 외부 공개 링크 자체의 차단은 아래 별도 범위다.
- 새 알림은 해당 지출 조회 범위의 수신자에게만 생성한다. 과거 일반 알림의 지출 본문은 비대표에게 금액 없는 안내로 반환한다. 테스트는 모의 발송뿐이다.
- 계정 변경 시 화면을 새로 구성하고 조회 실패 시 이전 목록을 지운다. 대표 외 프로젝트 전체 지출 집계는 표시하지 않는다.

## 검증
- 지출/승인/권한/알림/3PL API 30개 합성 테스트 통과. 타입 검사 및 서버 변경 파일 린트 통과.
- 실제 결제 요청 UI를 합성 세션·HTTP 응답으로 검증: 범위 표시, 은행정보 제한 안내, 권한 실패 후 새로고침 시 기존 기록 제거 통과.
- 결제 요청 기존 UI의 린트는 변경 전/후 동일한 52 errors + 2 warnings. 기존 전체 린트 부채를 해결했다고 주장하지 않는다.
- 실제 직원 인증·재무 데이터 쓰기·알림·송금 시험 없음.

## 별도 보안 변경 필요 — 미적용
읽기 전용 운영 메타데이터: public."PaymentRequest", public."Vendor", public."PaymentRequestAlert" 모두 RLS=false, anon/authenticated SELECT=true. 실제 행을 익명 조회하지 않았으며 실제 유출을 확인한 것이 아니다. 애플리케이션 제한만으로 DB REST 직접 접근이 차단됐다고 주장할 수 없다.
제안 승인 범위: 이 세 테이블에만 일반 RLS를 활성화하고 PUBLIC/anon/authenticated 직접 접근 권한을 차단한다. 서버용 기존 소유자/service_role 권한, 다른 테이블, 사용자 역할, 데이터는 유지한다. FORCE RLS 또는 service_role 회수는 하지 않는다. 실행 전 소유자/전체 ACL/정책과 서버 경로를 다시 확인한다. 트랜잭션 적용 후 무행 조회 및 기존 서버 읽기 검증, 실패 시 해당 트랜잭션 rollback. 적용 후 앱 rollback과 DB 접근 차단 유지를 우선하며 이전 노출 권한 복원은 별도 판단한다.

첨부 메타데이터 집계: PaymentRequest의 기존 attachment/attachments에 Google Drive 참조 254건(중복 가능). 파일 ID·내용·개인정보는 보고서에 저장하지 않았다. 실제 Drive permission은 아직 확인하지 않았다.
제안 승인 범위: 이 지출 첨부들만 파일 ID로 중복 제거 후 permissions 메타데이터 점검, 공통 자료와 중복 연결 여부 확인, 해당 파일의 anyone 공유 회수 및 인증 프록시 다운로드로 전환. 폴더 상속 권한이면 원본을 삭제하지 않고 승인된 비공개 지출 보관 위치로 이전/참조 교체하는 별도 계획이 필요하다. 신규 지출 업로드 역시 공개 링크 자동 부여 경로를 사용하지 않도록 구분하고 사용자·첨부 소유 연결을 검증해야 한다. 공유 권한 변경/이동/삭제는 현재 미실행. 복구는 보관한 해당 파일 ACL·참조를 기준으로 하며 광역 폴더 공유나 전체 Drive 권한을 바꾸지 않는다.
