# 이체 완료 표시 복구 검토

기준 운영 main: 6d7b446. 운영 데이터 변경·송금·배포 없이 준비한 수정이다.

## 원인
- 조회는 지정 이체담당자 ALL 예외지만 canActWithinScope 및 PATCH/batch는 write SELF/DEPARTMENT 범위여서 타직원 요청을 차단한다.
- batch는 지정 여부와 무관하게 TEAM_LEAD를 거부한다.

## 최소 변경
- 기존 활성 계정과 회사 지정 이체담당자 검사를 재사용한다.
- canCompleteTransfer를 일반 수정 범위와 분리한다. 일반 수정/삭제/승인은 그대로다.
- 요청자가 USER/TEAM_LEAD/CENTER_CHIEF인 승인 완료 건만 기록한다. 대표 ID·ADMIN/EXECUTIVE·요청자 미확인은 제외한다.
- 단건/일괄을 같은 서비스로 처리한다. 조건부 UPDATE와 트랜잭션으로 미승인 상태 덮어쓰기 및 중복 완료 시각/알림 생성을 방지한다.
- 재시도 시 이미 완료된 건은 noOp, 승인 취소 충돌은 409. 합성 시험 외 실제 요청 변경 없음.
- 별도 DB/역할/지속 인증 변경 없음. 기존 조회 노출 범위는 이번 변경으로 확대하지 않는다.

## 검증
- 신규 8개 + 기존 21개 합성 테스트 통과, tsc 통과.
- 서버/정책/테스트 린트 통과. 결제 요청 UI 기존 50 errors/2 warnings는 운영 6d7b446에서도 동일하게 재현됨.
- 실제 담당자 브라우저 클릭·운영 PostgreSQL 동시성·실제 알림 수신은 미검증. 합성 모의 트랜잭션 테스트와 구분한다.
- 운영 반영 전 별도 결과 보고. 보호 대상 폴더 정책 및 미배포 재무 개인정보 제한 변경은 포함하지 않는다.
