# NEXT 전환 계약

기존 주키 해시를 읽거나 복사하지 않는다. 키 생성/환경 설정은 지정된 브라우저 작업자만 수행한다.

## 환경변수
기존 주키 SHA256/ISSUED_AT/EXPIRES_AT를 유지하고 다음 네 값을 모두 추가한다.
- CRM_CORPORATE_INQUIRY_NEXT_SHA256
- CRM_CORPORATE_INQUIRY_NEXT_ISSUED_AT
- CRM_CORPORATE_INQUIRY_NEXT_EXPIRES_AT
- CRM_CORPORATE_INQUIRY_NEXT_ACCEPT_UNTIL

SHA256은 새 토큰 문자열 UTF-8의 소문자 hex64. 시간은 실제 UTC ISO8601 Z. 새 키 수명은 최대 90일(7776000000ms). NEXT 발급은 주키 발급 이상이어야 한다. ACCEPT_UNTIL은 NEXT 발급보다 늦고, NEXT 발급+24시간/주키 만료/NEXT 만료 중 가장 이른 시각 이하여야 한다. 통상 1시간을 권장한다. 발급시각을 뒤로 옮겨 중첩을 연장하지 않는다.

PREVIOUS와 NEXT는 동시 금지(빈 값도 설정으로 간주). 최대 두 키이며 부분 설정/중복 해시/잘못된 시간은 전체 fail-closed. 만료한 NEXT는 거부하지만 유효한 주키는 유지된다. NEXT 만료 후 홈페이지가 NEXT를 사용하면 접수 실패하므로 기한 안에 승격하거나 주키로 복귀해야 한다.

## 배포 순서
1. NEXT 없는 기존 환경으로 호환 코드 배포. 다른 11개 Cron 차단 유지.
2. 실제 새 키 생성, 기존 주키 그대로 + NEXT 네 값 설정 후 CRM 배포. PREVIOUS는 모두 미설정이어야 한다.
3. 홈페이지 TOKEN/ISSUED_AT/EXPIRES_AT를 새 값으로 설정·배포. 기존 동의/Origin 유지. 허가된 동일 요청 ID 검증은 브라우저 작업자가 수행한다.
4. 성공 확인 후 새 SHA256/실제 발급/만료를 주키 세 값으로 승격하고 NEXT 네 값을 같은 배포에서 전부 제거한다. 중간 환경 상태로 재배포하지 않는다.
5. 실패 시 중첩 기한 안에 홈페이지를 기존 정상 배포로 복귀할 수 있다. 기존 키를 추출하지 않는다. 이전 배포 URL의 환경은 별개이므로 전역 즉시 폐기를 주장하지 않는다.

## 알림
주키가 접수 보장의 기준이다. NEXT 단계에서는 기존 주키의 만료를 알리고, 승격 후 새 주키의 정확한 발급/만료로 알림과 중복 키가 전환된다. 과거 알림 기록은 삭제하지 않는다. 자동 승격/키 생성/자동 갱신 없음. CRON_SECRET 설정이 이번 배포에 반영될 수 있으므로 11개 기존 Cron의 차단을 재검증한다. 실제 알림/예약 실행 검증은 코드 검증과 구분한다.
