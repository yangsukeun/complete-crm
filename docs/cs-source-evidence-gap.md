# CS 휴가 원장 독립 자료 조사와 대조 준비

2026-11-04. Windows 브라우저 URL 안전 식별 중단을 유지했다. 브라우저 호출·원본 탭 조작·대체 경로로 Gemini 내용 읽기를 수행하지 않았다.

## 별개 허용 소스에서 확인한 것

- 작업 폴더의 기존 조사 기록과 `cs-tab-inventory.json`을 읽었다. 연결이 확인된 일일 보고서 시트 220탭의 제목·표본 헤더에는 연차/휴가 원장으로 특정할 근거가 없었다. 이 결과는 미조사 셀 전체에 해당 자료가 없다는 뜻은 아니다.
- Google Drive의 기존 연결에서 CS컴플리트/연차 키워드로 파일 목록만 검색했다. 다른 부서·과거 자료·계정정보 파일은 제목만 보고 내용을 열지 않았다. 기존 CS 자료 폴더의 목록에서도 현행 Gemini 원장으로 연결되는 내보내기를 식별하지 못했다.
- 사용자가 제공했던 링크 목록 스프레드시트 `11SWsjEBhF5_RNx9m9jt6DBIIBbMbwBOVU5sDBdm3ML4`의 메타데이터를 읽었다. 휴무 일정으로 명명된 과거 숨김 탭과 `26명` 탭을 확인했지만, 원본 연결로 간주하지 않았다. 숨김 해제/권한 변경 없음.
- `26명` 탭 gid=1394769425의 A1:H4 및 A5:C9만 읽었다. 2026년 3월 표기, 직원 헤더, 담당 업체 항목이 보였다. 고유 휴가 기록 ID/승인 상태/원본 저장소 연결은 해당 범위에서 확인되지 않았다. 개인 이름/휴가 기록은 코드나 이 문서에 옮기지 않았다.
- 따라서 새로 확보한 **407건 전체 원장 사본은 없고, 70건 차이의 원인과 원본 직원 ID↔CRM ID 매칭은 미확인**이다. 이미 승인된 운영 CRM DB와 원본 Gemini 데이터 저장소를 동일하다고 가정하지 않는다.

## 독립 구현

`cs-source-ledger-audit.ts`와 TEST의 원장 진단 패널을 추가했다. 입력은 페이지 내에서만 처리하며 원격 저장/계정 변경을 하지 않는다.

- 표시 총계, 카드 합계, 원시 기록 수, 고유 기록 ID 수를 분리한다.
- 동일 ID 반복/서로 다른 값 충돌, 직원 참조 누락, 승인/반려/취소/대기별 건수, 월별 건수, 미확인 상태·날짜·일수를 진단한다.
- 직원 매칭은 명시적 원본 ID/CRM ID 및 증거 참조를 요구한다. 중복 대응, 없는 ID, 비활성 CRM 계정은 검토 대상으로 남긴다. 이름 기반 자동 병합은 없다.
- `eligibleForReview`는 제출된 대응 증거의 구조적 적격 여부일 뿐 실제 신원 일치 인증이 아니다. `readyForImport`는 항상 false다. 합성 결과를 원본 대조 완료나 승인으로 취급하지 않는다.
- 입력 사본을 수정하지 않는다. 빈/부분 사본, 기록 충돌, 상태/단위 불명, 비활성·중복 ID를 합성 검사로 확인했다.

## 최소 필요한 원본 자료

1. 원본 CS컴플리트의 **표시 총계와 같은 범위**인 전체 휴가 원장 사본: 기록 고유 ID, 직원 원본 ID, 사용 날짜, 종류/단위/일수, 신청·승인·반려·취소 상태, 삭제/보관 상태(존재 시), 생성·수정 버전(존재 시). 메모·건강 사유는 건수 대조에 불필요하므로 제외 가능하다.
2. 사본의 관찰/내보내기 시각, 적용 필터·날짜 범위·페이지 수, 비활성/퇴사/삭제 항목 포함 기준. 화면의 407 및 카드 합계 337이 같은 기준인지 설명이 필요하다.
3. 원장에 등장하는 직원의 안정적인 원본 ID 목록과 부여/이월/기사용/원장 사용/조정/잔여, 적용 시작·종료일 및 단위. 누락 직원 ID는 추정 생성하지 않는다.
4. 원본 ID와 CRM ID의 대응 근거: 공통 사번/외부 ID 또는 관리자가 확인한 대응표. 동명이인은 이름만으로 연결하지 않는다. 계정 비밀번호·토큰은 필요 없다.

현재 사용자가 직접 확인 가능한 원본의 지원되는 내보내기로 위 사본을 작업 폴더에 제공하는 것이 최소 데이터 조치다. 원본 관리자 내보내기 기능 자체는 아직 확인하지 못했으므로 특정 버튼이 있다고 가정하지 않는다. 브라우저 안전 제한을 해제하거나 인증정보를 전달할 필요는 없다.
