# DB 맞추기 — 내가 할 일만 (순서대로)

> 레포에는 `schema.prisma`에 **`directUrl = env("DIRECT_URL")`** 이 있습니다.  
> **`npm run db:migrate`** 등은 `scripts/prisma-with-env.cjs` 를 거쳐 실행되며, `.env`에 `DIRECT_URL`이 없으면 **일단 `DATABASE_URL`을 복사**합니다.  
> ⚠️ **`DATABASE_URL`이 풀러(6543)뿐이면** 마이그레이션도 풀러로 가서 **처음 문제와 같아질 수 있으므로**, 아래처럼 **`DIRECT_URL`을 5432로 따로 넣는 것이 필수**입니다.

---

## 1) Supabase에서 값 복사 (브라우저)

1. [Supabase](https://supabase.com) → 본인 프로젝트
2. **Project Settings** → **Database**
3. **Connection string** 섹션:
   - **Transaction pooler** (또는 **Pooler**, 포트 **6543**) URI → 메모장에 **A** 로 저장 → 나중에 `DATABASE_URL`
   - **Direct connection** (또는 **Session**, 포트 **5432**) URI → 메모장에 **B** 로 저장 → 나중에 `DIRECT_URL`  
     - 없으면 호스트가 `db.<project-ref>.supabase.co` 이고 포트 **5432** 인 연결 문자열

비밀번호는 `[YOUR-PASSWORD]` 자리에 **Database password** 를 넣어 **완성된 URI** 로 만듭니다.  
URI 안에 `@`, `#`, `:` 가 비밀번호에 있으면 [URL 인코딩](https://www.urlencoder.org/)이 필요할 수 있습니다.

---

## 2) PC에서 `.env` 편집 (한 번만)

프로젝트 루트 `C:\Users\USER\complete-crm\.env` 파일을 연다.

```env
DATABASE_URL="1단계 A — 앱용 (pooler 6543 이어도 됨)"
DIRECT_URL="1단계 B — 반드시 Direct 5432 (마이그레이션 전용)"
```

- **둘 다 5432 직접 연결만 쓴다면** → 두 변수에 **같은 URI** 를 넣어도 됨 (`DIRECT_URL` 줄 생략해도 스크립트가 `DATABASE_URL`을 복사하지만, **둘 다 5432일 때만** 안전).
- **6543 풀러를 앱에 쓰는 경우** → `DIRECT_URL` 줄은 **절대 생략하지 말고** 5432 URI를 넣을 것.
- **저장** 후 파일 닫기.

`.env` 는 Git에 안 올라가므로, **팀원/배포 서버**에도 각각 같은 규칙으로 변수를 넣어야 한다.

---

## 3) 마이그레이션 적용 (터미널)

PowerShell:

```powershell
cd C:\Users\USER\complete-crm
npm run db:migrate
```

정상일 때 예:

- `Applying migration \`...\``
- 또는 `No pending migrations to apply.`

---

### `Error: P3005` (The database schema is not empty)

DB에 이미 테이블이 있는데 Prisma 마이그레이션 이력이 비어 있을 때 납니다. **아래 순서**로 한 번만 정리합니다.

1. **스키마를 DB에 맞추기** (누락된 테이블·enum 등 추가):

   ```powershell
   npm run db:push
   ```

2. **지금까지의 마이그레이션을 “이미 적용됨”으로 표시** (SQL은 다시 실행하지 않음):

   ```powershell
   npm run db:baseline
   ```

3. 다시 확인:

   ```powershell
   npm run db:migrate
   ```

   → `No pending migrations` 가 나오면 성공.

> `db:push` 없이 `db:baseline`만 하면, 아직 DB에 없는 변경은 반영되지 않습니다. 반드시 **push → baseline → migrate** 순서를 지키세요.

---

끝나면:

```powershell
npm run dev
```

(이미 켜져 있으면 **한 번 껐다가** 다시 실행)

## 4) 확인 (선택, Supabase SQL Editor)

```sql
SELECT e.enumlabel
FROM pg_enum e
JOIN pg_type t ON e.enumtypid = t.oid
WHERE t.typname = 'NotificationType'
ORDER BY e.enumsortorder;
```

`BOARD_MENTION`, `TASK_BODY_MENTION` 이 보이면 enum 쪽은 맞는 편이다.

```sql
SELECT tablename FROM pg_tables
WHERE schemaname = 'public' AND tablename IN ('TaskMention', 'TaskRevision');
```

## 문제 시

- **`Environment variable not found: DIRECT_URL`**  
  → `.env` 에 `DIRECT_URL=` 줄을 추가했는지, 오타 없는지 확인.

- **`Error: P1001: Can't reach database`**  
  → 방화벽/VPN, 비밀번호, `sslmode=require` 누락, 호스트 오타 확인.

- **`migrate deploy` 가 이전과 같이 조용함**  
  → `DIRECT_URL` 이 정말 **5432** 인지, Supabase 대시보드에서 복사한 **Direct** 문자열인지 다시 확인.

자세한 SQL 수동 적용은 `prisma/DB_TASK_MENTION.md` 참고.
